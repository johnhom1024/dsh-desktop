# dsh-app Desktop Host Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** 做一个极薄的 macOS Electron 桌面 host：不 fork、不改官方 UI，按「复用本机 3080 → PATH/npx → 内置兜底」启动或连接 `dsh web`，窗口一直显示官方页面，并支持连 NAS 远程实例。

**Architecture:** 独立仓库。主进程只负责运行时解析、子进程生命周期、窗口和托盘。Renderer 默认只加载已就绪的官方 Web UI；连接设置用独立原生窗口，不注入官方页面。远程模式只连 HTTP，不在本机 spawn。

**Tech Stack（已锁定）：**

- 包管理：`pnpm`（`packageManager` 字段钉版本；禁止 npm / yarn）
- 运行时壳：Electron（不是 Tauri）
- 语言：TypeScript `strict` + ESM（`"type": "module"`）
- 主进程编译：`tsc` 出 `dist/`，v1 不上 electron-vite / webpack / esbuild 打包
- 测试：Node 内置 test runner + `tsx --test`（不上 Vitest / Jest）
- 脚本：一律 `cross-env`，禁止 Unix-only `VAR=value`
- 类型检查：显式 `tsc --noEmit`
- 设置页：原生 HTML + 一小段 TS，不上 React / Vue
- 依赖：v1 只加 `electron`、`typescript`、`tsx`、`cross-env`；`@deepseek-ai/dsh` 留到内置兜底任务再加
- 不做：ESLint/Prettier 基建、electron-builder、自动更新、签名公证

不引入通用 EventBus / Context / 字符串 registry。

**Repo:** `/Volumes/Backup/project/dsh-app`（目前只有 `IDEA.md`，还不是 Git 仓库）

## Proposed approach

```text
Electron Main
  ├── resolveRuntime()
  │     1. probe http://127.0.0.1:3080
  │     2. which dsh && dsh --version
  │     3. find npx cache @deepseek-ai/dsh
  │     4. bundled node_modules/@deepseek-ai/dsh
  │     5. saved remote URL (settings)
  ├── spawn `dsh web --port 0`  （仅本地启动路径）
  ├── waitUntilReady(url)
  ├── BrowserWindow.loadURL(url)
  └── Tray：显示/隐藏窗口；退出时杀掉本进程拉起的子进程
```

设置存 `app.getPath('userData')/settings.json`：

```ts
type ConnectionMode = 'smart' | 'local-only' | 'remote'

type Settings = {
  connectionMode: ConnectionMode
  remoteUrl?: string // e.g. http://192.168.31.229:3080
}
```

默认 `smart`。远程 URL 必须是 `http:` / `https:`，禁止 `file:`。

模块按职责拆，直接函数调用，不要 Events / Context：

- `src/main/settings.ts` — 读写 settings
- `src/main/probe.ts` — HTTP 探测官方 Web UI
- `src/main/runtime.ts` — 解析运行时来源
- `src/main/harness-process.ts` — spawn / 等就绪 / 退出清理
- `src/main/window.ts` — 主窗口 + 连接设置窗口
- `src/main/tray.ts` — 托盘
- `src/main/index.ts` — 启动编排
- `src/preload/settings.ts` — 仅设置窗口用的窄 IPC
- `src/renderer/settings.html` + `settings.ts` — 连接设置 UI

主窗口 renderer 不跑自己的前端框架，直接 `loadURL` 官方页面。

安全：

- 主窗口：`nodeIntegration: false`，`contextIsolation: true`，无 preload（或空 preload）
- 设置窗口：单独 preload，只暴露 `getSettings` / `saveSettings` / `reconnect`
- `setWindowOpenHandler`：外链用系统浏览器
- 导航白名单：回环地址，或用户保存的 remote origin

### Task 3: 运行时解析（先写测试）

**Objective:** 按固定顺序选出连接目标，顺序必须一眼能看出来。

**Files:**

- Create: `src/main/runtime.ts`
- Create: `src/main/runtime.test.ts`

```ts
export type RuntimeSource =
  | { kind: 'reuse-local'; url: string }
  | { kind: 'path-dsh'; command: string }
  | { kind: 'npx-cache'; packageRoot: string; version: string }
  | { kind: 'bundled'; packageRoot: string; version: string }
  | { kind: 'remote'; url: string }
  | { kind: 'none' }

export async function resolveRuntime(input: {
  settings: Settings
  probe: (url: string) => Promise<boolean>
  whichDsh: () => Promise<string | null>
  findNpxCache: () => Promise<{ packageRoot: string; version: string } | null>
  bundled: { packageRoot: string; version: string } | null
}): Promise<RuntimeSource>
```

规则：

- `connectionMode === 'remote'` 且 `remoteUrl` 有效 → 直接 `{ kind: 'remote', url }`，不再探测 3080
- `smart` / `local-only`：
  1. probe `http://127.0.0.1:3080` 成功 → `reuse-local`
  2. `whichDsh()` 有值 → `path-dsh`
  3. `findNpxCache()` 有值 → `npx-cache`
  4. `bundled` 有值 → `bundled`
  5. 否则 `none`
- `local-only` 不允许走到 remote

测试用假 `probe` / `whichDsh` / `findNpxCache`，覆盖上面每条分支。不要打真实文件系统。

Commit: `feat: resolve dsh runtime in explicit order`

### Task 5: 拉起 `dsh web` 并等待就绪

**Objective:** 本地启动路径可测、可清理。

**Files:**

- Create: `src/main/harness-process.ts`
- Create: `src/main/harness-process.test.ts`

```ts
export async function startHarnessWeb(opts: {
  command: string
  args: string[]
  cwd?: string
  env?: NodeJS.ProcessEnv
  probe: (url: string) => Promise<boolean>
}): Promise<{ url: string; child: ChildProcess; stop: () => Promise<void> }>
```

约定：

- 优先 `dsh web --port 0`，从 stdout/stderr 解析 `http://127.0.0.1:<port>`
- 解析不到就失败，不要猜 3080（3080 留给「复用已有实例」）
- 超时（默认 20s）未就绪 → `stop()` 并抛错
- `stop()` 杀掉整棵进程树；app 退出时必须调用
- **复用 / 远程路径不走这个函数**

测试：用一个假 CLI 脚本往 stdout 打 `http://127.0.0.1:<port>`，同时起一个带 DeepSeek title 的 HTTP server。

Commit: `feat: spawn dsh web and wait until ready`

## Risks, tradeoffs, and open questions

- **官方还是 RC。** 内置 `@deepseek-ai/dsh` 会过期。智能回退降低这个问题：本机已有实例时根本不用内置包。
- **`--port 0` 输出格式可能变。** `harness-process` 必须把解析写成可测函数；官方一改只改这一处。
- **复用 3080 时不要在退出时杀掉它。** 那可能是用户自己的浏览器 / CLI 实例。
- **npx 缓存布局因 npm 版本而异。** 用「扫 package.json name」而不是写死某一层目录。
- **NAS 上现在不一定跑着 dsh。** 远程是设置项，不是启动默认。
- **macOS Gatekeeper。** v1 先 `electron .` 跑通；签名公证另开一轮。
- **备份盘路径。** 仓库在 `/Volumes/Backup/project/dsh-app`，盘没挂会丢工作区。

未决但可延后：

- 应用显示名（暂用 `dsh-app` / DeepSeek Harness）
- 是否把默认远程预填 `http://192.168.31.229:3080`
- 是否做 CNB 仓库和 Dokploy 发布（有产品形态再做）
